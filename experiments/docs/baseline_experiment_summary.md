## 1. บทนำและวัตถุประสงค์
การทดลองนี้เป็นการรันระบบสวีปพารามิเตอร์ (Sweep) บนโมเดลกลุ่ม Baseline เพื่อค้นหาการตั้งค่าที่ช่วยปรับปรุงค่า **Mean Absolute Error (MAE)** ให้ต่ำที่สุด ซึ่งใช้การแปลงข้อความเป็นเวกเตอร์ผ่าน TF-IDF (ทั้งระดับคำและตัวอักษร) แล้วเรียนรู้ด้วยแบบจำลอง XGBoost 

มีจุดประสงค์หลักในการประเมินประสิทธิภาพในมิติต่างๆ ดังนี้:
1. การจัดการปัญหาข้อมูลไม่สมดุล (Class Imbalance) ด้วยการ Undersampling/Oversampling และถ่วงน้ำหนัก (Class Weights)
2. การปรับแต่งลักษณะข้อมูล (Feature Engineering) เช่น ขนาดคลังคำศัพท์ (Vocabulary size), การลดมิติด้วย LSA และการเพิ่ม Hand-crafted features (Extra Features)
3. การปรับแต่งโมเดล XGBoost (ความลึก, จำนวนรอบฝึก, อัตราการเรียนรู้)
4. การทำ Data Augmentation สำหรับกลุ่มคลาสดาวน้อย (1-3 ดาว)

## 3. วิเคราะห์ผลการทดลองตัวเด่น (Deep Dive)

### 🥇 ผู้ชนะเลิศ: `b6_no_extra_features` (MAE 0.6428)
- **การเปลี่ยนแปลง:** ปิดการใช้งาน `BASELINE_USE_EXTRA_FEATURES` (ลดฟีเจอร์ความยาวรีวิว, จำนวนคำ, และจำนวนคำปฏิเสธภาษาไทย)
- **ผลลัพธ์:** MAE ลดลงอย่างมีนัยสำคัญจากเดิม **0.6886** ลงเหลือ **0.6428** พร้อมกับค่า **F1-Macro ที่พุ่งสูงขึ้นเป็น 0.4248** (เพิ่มขึ้นจากเดิมเกือบเท่าตัว) และ **Accuracy ขยับขึ้นมาอยู่ที่ 0.4620**
- **บทวิเคราะห์:** 
  ฟีเจอร์อย่างความยาวข้อความและสถิติคำ (Hand-crafted features) สำหรับโมเดลต้นไม้อย่าง XGBoost มักกลายเป็นตัวสร้างสัญญาณรบกวน (Noise) หรือทำให้เกิดอาการ Overfitting สูง เนื่องจากผู้รีวิวร้านอาหารแต่ละคนเขียนยาวสั้นไม่เท่ากัน เช่น รีวิวยาวอาจจะติชมปนกัน หรือรีวิวสั้นแต่สื่ออารมณ์ได้ชัดเจนกว่า การตัดลักษณะเหล่านี้ทิ้งไปช่วยบีบให้โมเดล XGBoost โฟกัสไปที่เวกเตอร์ความถี่ของคำ (TF-IDF) ซึ่งระบุเจตนารมณ์ความรู้สึกและข้อมูลเชิงคุณภาพได้ดีกว่าอย่างแท้จริง

### 🥈 อันดับสอง: `b4_lsa_500_no_char` (MAE 0.6757)
- **การเปลี่ยนแปลง:** ใช้การทำ LSA (ลดมิติข้อมูล) ความละเอียด 500 มิติ และปิดการแปลง Char-TF-IDF
- **บทวิเคราะห์:** การลดมิติช่วยควบคุมความซับซ้อนของข้อมูลและคัดกรองข้อมูลรบกวนได้พอสมควร แต่ยังสู้การโมเดลที่พิจารณารายละเอียดคำตัวอักษรโดยตรง (แบบไม่มี Extra Features) ไม่ได้

### ❌ จุดอันตราย: `d1_trunc200` (MAE 0.7323)
- **การเปลี่ยนแปลง:** จำกัดตัวอักษรของรีวิวให้สั้นมากเพียง 200 อักษร
- **บทวิเคราะห์:** การตัดรีวิวให้สั้นเกินไปทำให้สูญเสียข้อมูลบริบท (Context) สำคัญ โดยเฉพาะรีวิวภาษาไทยที่มักมีการอารัมภบทก่อนจะเขียนติชมร้านอาหารจริง ๆ ในช่วงกลางหรือท้าย ส่งผลให้ MAE แย่ลงชัดเจน

## 4. ปัญหาและข้อผิดพลาดในการทดลอง (Failed Variants)

มี 5 Variant ที่ล้มเหลวระหว่างการทดลอง โดยสามารถสรุปสาเหตุเชิงระบบและทางออกได้ดังนี้:

### 4.1 ข้อผิดพลาดประเภทประเภทข้อมูลขัดแย้ง (Type Conflict)
* **เวอร์ชันที่เกิด:** `b1_tfidf_12k_bigram`, `b2_tfidf_5k_trigram`, `b5_char_only_6k`
* **สาเหตุ:** การตั้งค่า `TFIDF_NGRAM_RANGE` ในไฟล์ YAML เป็น `[1, 2]` ซึ่ง YAML จะอ่านค่าเป็นชนิดข้อมูล **List (ใน Python)** แต่คลาส `TfidfVectorizer` ของ scikit-learn บังคับว่าต้องส่งผ่านข้อมูลชนิด **Tuple** เท่านั้น
* **ข้อความผิดพลาด:** 
  > `The 'ngram_range' parameter of TfidfVectorizer must be an instance of 'tuple'. Got [1, 2] instead.`
* **ทางแก้ไข:** ในโค้ดตัวอ่าน Manifest หรือสคริปต์สวีป ควรแปลงตัวแปรดังกล่าวให้เป็น `tuple()` เสมอก่อนนำส่งเข้าเวกเตอร์ไรเซอร์ 

### 4.2 ข้อผิดพลาดโครงสร้างคลาสในโหมด Regression
* **เวอร์ชันที่เกิด:** `c4_regression_mode`
* **สาเหตุ:** เมื่อเปิดการตั้งค่า `BASELINE_USE_REGRESSION = True` ตัวแบบจำลอง XGBoost จะเปลี่ยนผลลัพธ์ทำนายเป็นค่าต่อเนื่องแบบมิติเดียว (Shape: `(1368,)`) แต่ในโค้ดรันการประเมิน หรือโค้ดคำนวณน้ำหนักยังคงพยายามใช้งานในแบบ Classification หลายคลาส (Shape: `(1368, 5)`) จึงไม่สามารถกระจายอาเรย์เปรียบเทียบกันได้
* **ข้อความผิดพลาด:** 
  > `operands could not be broadcast together with shapes (1368,) (1368,5)`

## 5. ข้อเสนอแนะและการดำเนินการถัดไป (Action Items)

1. **นำเข้าการตั้งค่าที่ดีที่สุด:** ได้ทำการเปลี่ยนค่าเริ่มต้นใน `src/rris/config.py` ให้เป็น `BASELINE_USE_EXTRA_FEATURES = False` เรียบร้อยแล้ว เพื่อให้แน่ใจว่าโมเดลที่จะใช้หลังจากนี้ใช้การเรียนรู้ที่มี MAE ต่ำสุด
2. **แก้ไขระบบอ่านข้อมูล Sweep (YAML Parser):** ปรับโค้ดสวีปเพื่อสลับโครงสร้างแปลง List เป็น Tuple อัตโนมัติ เพื่อให้สามารถรันตัวแปรประเภท N-Gram range อื่นๆ ที่ยังตกค้าง เช่น Trigram ได้สำเร็จ
3. **ปรับแก้โหมดถดถอย (Regression Mode):** ปรับปรุงฟังก์ชันคำนวณ Metric การประเมินผลการเรียนรู้ ให้รองรับรูปแบบข้อมูล 1 มิติ เพื่อทดลองประโยชน์ของ Ordinal regression ในอนาคตต่อไป
